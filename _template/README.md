# <产品> <版本> <漏洞类型> (<CVE 编号>)

| 项 | 内容 |
|---|---|
| CVE | `CVE-YYYY-NNNNN` |
| 产品 / 版本 | `产品名 1.2.3`（受影响范围） |
| 漏洞类型 | `RCE` / `SQLi` / `SSRF` ... |
| 危害 | 未授权命令执行 / 数据泄露 / 认证绕过 |
| 前置条件 | 无需认证 / 需要普通用户 / 需要特定配置 |
| 验证方式 | 回显特征串 / 延时对比 / 唯一标记 |
| 破坏性 | 无（仅只读验证） |

## 漏洞描述

一两段话说清：漏洞在哪个组件、触发点是什么、根因是什么。

## 影响版本

- 受影响：`x.y.z` ~ `a.b.c`
- 不受影响：`>= d.e.f`

## 验证原理

说明脚本发了什么请求、看什么响应来判定。要能让别人不用跑脚本也能理解判定逻辑。

## 使用方法

```bash
python3 poc.py -u http://target:8080
```

## 预期输出

```text
[*] GET http://target:8080/xxx -> HTTP 200 (0.31s, 1024 bytes)
[+] 目标回显了验证标记, 疑似存在漏洞
[RESULT] VULNERABLE
```

## 修复建议

- 升级到 `d.e.f` 及以上
- 临时缓解措施（如关闭某功能、加 WAF 规则）
