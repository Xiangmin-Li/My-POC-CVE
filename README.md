# my-poc-cve

漏洞 PoC 验证脚本集合。每个漏洞一个独立目录，目录名即索引，脚本只做**非破坏性验证**。

目标是：看到目录名就知道打的是什么，进目录就能跑，跑完能看懂结果。

## 目录命名规范

```text
<框架>-<版本>-<漏洞类型>-<CVE编号>
```

| 字段 | 规则 | 示例 |
|---|---|---|
| 框架 | 官方产品名，保持官方大小写 | `Struts2`、`Fastjson`、`Log4j`、`ThinkPHP` |
| 版本 | 受影响版本；区间用 `to` 连接，多点用 `_` | `2.5.16`、`5.0.0_to_5.3.0` |
| 漏洞类型 | 取自下方词表，保持写法一致 | `RCE`、`Deserialization`、`SQLi` |
| CVE 编号 | `CVE-YYYY-NNNNN`；无 CVE 用 `CNVD-...` 或 `NO-CVE-<标识>` | `CVE-2017-5638` |

全 ASCII、用 `-` 分隔、不含空格和中文，保证在任何系统上都能直接 `cd` 进去。

示例：

```text
Struts2-2.5.16-RCE-CVE-2017-5638/
Fastjson-1.2.24-Deserialization-CVE-2017-18349/
Log4j-2.14.1-JNDI-CVE-2021-44228/
ThinkPHP-5.0.23_to_5.1.30-RCE-CVE-2018-20062/
```

## 漏洞类型词表

| 类型 | 含义 |
|---|---|
| `RCE` | 远程命令执行 |
| `Deserialization` | 反序列化 |
| `JNDI` | JNDI 注入 / Log4Shell 类 |
| `SQLi` | SQL 注入 |
| `SSRF` | 服务端请求伪造 |
| `LFI` | 本地文件包含 / 任意文件读取 |
| `PathTraversal` | 路径穿越 |
| `XXE` | XML 外部实体 |
| `XSS` | 跨站脚本 |
| `AuthBypass` | 认证绕过 / 越权 |
| `FileUpload` | 任意文件上传 |
| `InfoLeak` | 信息泄露 |
| `CommandInjection` | 命令注入（非直接 RCE 场景） |

## 单个漏洞目录结构

```text
<框架>-<版本>-<漏洞类型>-<CVE编号>/
├── poc.py       # 验证脚本，单文件可运行
└── README.md    # 漏洞说明、用法、预期输出、修复建议、验证记录
```

参考 `_template/` 里的两个模板文件，新增时直接复制。

## 脚本规范

所有 `poc.py` 遵循同一套接口，便于批量调用：

| 项 | 约定 |
|---|---|
| Python | 3.8+，单文件，只依赖 `requests` |
| 参数 | `-u/--url` 必填；`-t/--timeout`；`--proxy`；`-k` 跳过 TLS 校验 |
| 退出码 | `0` 漏洞存在 / `1` 不存在 / `2` 参数或网络错误 |
| 输出前缀 | `[*]` 过程 / `[+]` 命中 / `[-]` 未命中 / `[!]` 错误 / `[RESULT]` 结论 |
| 判定方式 | 回显特征串、延时对比、唯一标记，三者组合 |

**非破坏性约束**（硬性要求）：

- 不写入文件、不修改配置、不创建账号、不落 webshell
- 需要证明命令执行时，只用 `echo <唯一串>` 或 `id` 这类无副作用命令
- 需要证明文件读取时，只读 `/etc/passwd` 或 `win.ini` 这类非敏感只读文件
- 任何脚本必须能对「不存在的目标」安全返回 `1`，不能因为打不通就当漏洞

## 快速使用

```bash
pip install -r requirements.txt

# 跑单个 PoC
python3 Struts2-2.5.16-RCE-CVE-2017-5638/poc.py -u http://target:8080

# 走代理 / 忽略证书
python3 <目录>/poc.py -u https://target -k --proxy http://127.0.0.1:8080

# 用退出码批量判断
python3 <目录>/poc.py -u http://target >/dev/null 2>&1 && echo VULN || echo SAFE
```

## 新增一个 PoC 的流程

1. 按命名规范建目录
2. 复制 `_template/poc.py` → `<目录>/poc.py`，改 `build_payload()` 与判定逻辑
3. 复制 `_template/README.md` → `<目录>/README.md`，填漏洞信息
4. 本地验证三种情况：**有漏洞 / 无漏洞 / 目标不可达**
5. 在目录 README 的「验证记录」里写清日期、靶场环境、实际输出
6. 提交，消息格式：`feat(<CVE编号>): 新增 <产品> <类型> PoC`
